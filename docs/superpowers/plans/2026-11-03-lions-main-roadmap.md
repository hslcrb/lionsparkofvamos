# 라이온즈 메인 및 공동 응원 구현 계획

> 상태: 계획만 작성. 구현·데이터 연동·Blender 제작·기능 배포는 후속 작업이다.

**목표:** 팬이 삼성 경기와 공식 시청 경로를 확인하고 함께 응원할 수 있는 모바일 중심 메인을 만든다.

**구조:** 기존 Next.js 메인과 Cloudflare Worker/Durable Object를 기반으로 정보 제공, 실시간 응원, 공식 미디어를 분리한다. 외부 데이터와 권리 조건을 먼저 확인하고, 실시간 확장은 측정 결과에 따라 단계적으로 결정한다.

**기술:** TypeScript, Next.js, Cloudflare Workers 및 Durable Objects, 허용된 공식 데이터·YouTube 임베드.

**기획:** [메인 팬 경험](../../design/lions-main-fan-experience.md). 경기장 참고 사진은 [`assets/blender/references`](../../../assets/blender/references)에 보존한다.

## 전체 제약

- 이사만루체와 삼성 아이덴티티를 쓰고 근거 없는 AI식 카피를 넣지 않는다.
- KBO 경기 일정과 CGV 상영 일정은 별개이며 공개·허용된 출처만 연동한다. 미발표와 실패를 정상 상태로 처리한다.
- 비상업적 비공식 팬사이트임을 밝히고 미디어·음원별 권리를 확인한다.
- YouTube 플레이어와 댓글은 분리하며 모바일·키보드·움직임 감소 설정을 지원한다.
- VAMOS Blender 공간은 이 계획에서 문서만 작성한다. 기존 라팍월드는 수정 범위가 아니다.

## 단계와 완료 조건

### 1. 화면 구조와 정보 위계

- [ ] `src/App.tsx`, `src/style.css` 및 필요한 메인 전용 컴포넌트에서 첫 화면, 경기 정보, 공동 응원, 공식 미디어의 읽기 순서를 구현한다.
- [ ] 실제 구호는 구단 공식 자료에서 확인하고, 기능 설명과 비공식·비상업 표기를 간결하게 정리한다.
- [ ] 320·390·768px 및 데스크톱에서 폰트 로딩과 대체, 긴 문구, 200% 확대, 키보드 조작을 확인한다.

### 2. 공식 일정과 시청 경로

- [ ] KBO와 CGV의 제공 방식·이용 조건을 확인하고, 허용된 피드가 없으면 출처와 확인 시각이 있는 수동 검수 데이터 및 공식 링크를 사용한다.
- [ ] 경기와 극장 편성을 별도 모델로 두고 한국 시간, 장소, 원본 링크, 확인 시각, 미발표·정상·순연·취소·매진·확인 불가 상태를 표현한다. 해당되지 않는 상태는 표시하지 않는다.
- [ ] 날짜 변경, 오래된 정보, 외부 서비스 실패와 비어 있는 편성을 검증하고 잘못된 확정 일정을 표시하지 않는다.

### 3. 댓글과 응원 경험

- [ ] `worker/`의 실시간 방과 `src/hooks/use-cheer-room.ts`의 현재 계약을 먼저 점검하고 댓글 작성·목록·이벤트 ID·스냅샷·재연결 계약을 명시한다.
- [ ] 서버 검증, 전송 제한, 중복 방지와 텍스트 안전 표시를 구현하고, 신고·숨김·운영자 대응·보관 및 삭제 정책을 마련한다.
- [ ] 별도 댓글 레인과 정적 최근 목록, 일시정지, 움직임 감소·스크린리더 대안을 구현한다. 오프라인·전송 실패·재연결 상태를 확인한다.
- [ ] 잘못된 입력, 중복 메시지, 다중 접속, 신고와 연결 복구를 검증한다.

### 4. 동시 접속과 비용

- [ ] 현재 단일 Durable Object의 쓰기·팬아웃을 기준으로 계수 배치와 전송 묶음의 정확도 및 지연을 비교한다. hibernation 후 필요한 상태를 복원한다.
- [ ] 100명, 1,000명, 그 이상 단계의 연결·응원·댓글·동시 재접속 부하를 시험한다. 연결 성공률, p50/p95/p99 지연, 누락·중복, 복구 시간, 객체 CPU·저장 쓰기와 예상 비용을 기록한다. 이 숫자는 실험 규모이며 지원 보장이 아니다.
- [ ] 측정 결과에 따라 샤딩 여부를 결정하고 전역 합계의 지연·정확도와 샤드 간 순서 정책을 검증한다.

### 5. 공식 영상과 응원가

- [ ] 공식 동영상과 KBO·구단·CGV 페이지를 검수해 제공자와 원본 링크를 표시한다. 삽입 허용 여부, 최소 크기, 재생 오류와 대체 링크를 확인한다.
- [ ] ‘나의 라이온즈’와 ‘치고 달려라’ 등 후보별 공식 명칭, 제공처, 저작권·녹음·실연 권리 및 배포 범위를 확인한다. 허락이 불확실한 자산은 자체 호스팅하지 않는다.
- [ ] 음악 켜기·끄기, 기존 낮은 음량, 사용자 조작과 자동재생 차단 시 상태를 검증한다.

### 6. VAMOS 응원관 사전 설계

- [ ] Blender MCP로 차후 제작할 공간의 레퍼런스·좌석·화면·조명·시점·동선·충돌·모바일 예산과 자산 권리를 문서화한다.
- [ ] 3D 모델과 응원·미디어 데이터의 경계를 정의한다. 별도 구현 요청 전까지 Blender 파일, 모델 또는 기능 코드를 만들지 않는다.

### 7. 통합 및 배포

- [ ] 관련 단위·통합 검사와 모바일/데스크톱 브라우저 실사용 검증을 수행한다. `npm run check`와 로컬 Worker 경로·WebSocket 검증을 실행한다.
- [ ] 사용자 요청에 따라 기능 브랜치에서 검토 후 `main`에 병합·푸시하고, Cloudflare 빌드 결과와 운영 화면·공식 링크·실시간 연결을 확인한다.

## 착수 전 확인 사항

공식 데이터 제공·사용 조건, 음원과 미디어 권리 범위, 댓글 운영 담당 및 보관·삭제 기간, 시험할 동시 접속 규모와 비용 한도는 아직 확정되지 않았다. 확인 전에는 추측을 사실처럼 구현하거나 공개하지 않는다.
